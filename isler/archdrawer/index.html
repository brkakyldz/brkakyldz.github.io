ArchDrawer

Your repository’s architecture, read from the code by your own Claude Code or Codex. Every part it draws names the files behind it, and you can edit the drawing by hand or in plain words, then export it sized for a README, a slide or a LinkedIn post.Reponun mimarisi, kendi Claude Code’un ya da Codex’in koddan okuduğu haliyle. Çizdiği her parça arkasındaki dosyaları gösteriyor; çizimi elle ya da düz cümlelerle düzenleyip bir README, bir sunum ya da bir LinkedIn postu için doğru boyutta dışa aktarabiliyorsun.

In shortKısaca

Problem
A diagram drawn by hand is out of date by the next refactor, and one a chatbot draws from your description is only as right as the description.Elle çizilen bir diyagram bir sonraki refactor’da eskiyor; bir sohbet botunun senin anlatımından çizdiği ise ancak o anlatım kadar doğru.
What it doesNe yapıyor
Your own coding agent reads the repository, keeps what it finds as facts that point back to real files and lays them out as a drawing you can edit. One drawing file holds the facts once and a layout per channel, so a README drawing and a LinkedIn image never disagree.Kendi kodlama agent’ın repoyu okuyor, bulduklarını gerçek dosyalara işaret eden bilgiler olarak saklıyor ve düzenleyebileceğin bir çizime döküyor. Tek bir çizim dosyası bilgileri bir kez, her kanal için ayrı bir yerleşimle tutuyor; böylece README çizimi ile LinkedIn görseli hiçbir zaman çelişmiyor.
Key decisionTemel karar
No model API and no key. It runs on the Claude Code or Codex subscription you already have, the engines get read-only tools, and code checks that every file they name exists before anything is drawn.Model API’si de anahtar da yok. Zaten sahip olduğun Claude Code ya da Codex aboneliğiyle çalışıyor; motorlar yalnızca okuyabilen araçlar alıyor ve bir şey çizilmeden önce kod, adı geçen her dosyanın var olduğunu kontrol ediyor.
